# Support

Thanks for using SinterDB.

This document explains where to go when you need help, want to report a problem, or have a question about a SinterDB project.

## Questions and Help

For general questions about a project, first check:

- The repository's `README.md`
- Available documentation
- Existing GitHub issues and discussions
- Repository-specific contribution or support guidelines

If you still need help, open a discussion or issue in the relevant repository.

## Bug Reports

If you believe you found a bug, report it in the repository where the issue occurs.

Before opening a new issue:

- Check whether the problem has already been reported
- Make sure you are using a currently supported version
- Gather relevant logs, error messages, and reproduction steps

A useful bug report should include:

- The affected project
- The version or commit
- Your environment
- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- Relevant logs or error output

## Feature Requests

Feature requests should be submitted to the repository they relate to.

Please describe:

- The problem you are trying to solve
- The behavior or feature you are proposing
- Why it would be useful
- Any alternatives you considered

For larger changes, opening a discussion before implementation is encouraged.

## Security Issues

Do **not** report security vulnerabilities through public issues, discussions, or pull requests.

Use the security reporting process defined by the affected repository.

If GitHub Private Vulnerability Reporting is enabled for that repository, use the **Security** tab and select **Report a vulnerability**.

## Repository-Specific Support

Individual SinterDB repositories may define additional support instructions.

When repository-specific guidance exists, it takes precedence over this organization-wide document.

## Response Expectations

SinterDB is an actively developed open-source project.

Response times may vary depending on maintainer availability, issue complexity, and project priority.

Well-documented reports with clear reproduction steps are generally easier to investigate and resolve.
